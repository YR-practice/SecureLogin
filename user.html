Симетричне шифрування

У симетричних алгоритмах для шифрування та дешифрування використовується один і той самий секретний ключ. Відправник і одержувач мають заздалегідь узгодити ключ і зберігати його в таємниці.

Відкритий текст M
→
Шифрування EK
→
Шифротекст C
→
Дешифрування DK
→
Відкритий текст M
C = EK(M)     M = DK(C)

Стійкість залежить від

  • надійності алгоритму (неможливо розшифрувати без ключа, аналізуючи лише шифротекст);
  • секретності ключа, а не алгоритму (принцип Керкгоффса);
  • неможливості обчислити ключ, навіть знаючи багато пар «відкритий текст — шифротекст».

Відомі алгоритми

  • AES — сучасний стандарт (блок 128 біт, ключ 128/192/256 біт);
  • DES / 3DES — застарілі, DES вразливий через короткий ключ (56 біт);
  • ChaCha20, Blowfish, ГОСТ 28147-89 / «Калина».

Недолік

Проблема розподілу ключів: якщо ключ перехоплено, зловмисник отримає доступ до всієї зашифрованої інформації. Тому на практиці симетричне шифрування поєднують з асиметричним (наприклад, у TLS/HTTPS).

У цьому застосунку

Дані користувачів шифруються алгоритмом AES-256-GCM (Web Crypto API) із ключем, виведеним через PBKDF2, і записуються в localStorage. Перегляньте їх у DevTools → Application → Local Storage.
